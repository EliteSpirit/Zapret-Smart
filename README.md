# Zapret Smart

GUI для обхода DPI на Windows со встроенным конструктором и поиском стратегий. Движок — форк `nfq/` из [zapret](https://github.com/bol-van/zapret) (winws + WinDivert).

## Состав

| Путь | Что это |
|---|---|
| `engine/nfq` | Исходники движка (форк zapret, MIT). Источник и коммит — `engine/UPSTREAM.txt` |
| `engine/files/fake` | Комплектные фейковые пакеты для стратегий |
| `src/ZapretSmart.Core` | Формат стратегий, белый список опций движка, сборка командной строки, запуск движка, поиск стратегий, отчёт для сообщества |
| `src/ZapretSmart.App` | Интерфейс (Avalonia): обход, конструктор стратегий, поиск, настройки |
| `strategies/presets` | Встроенные стратегии |
| `lists` | Встроенные списки доменов |

## Формат стратегии

```json
{
  "id": "general-multisplit",
  "name": "Общая: fake + multisplit",
  "intercept": { "tcp": "80,443", "udp": "443" },
  "profiles": [
    { "hostlist": "general", "args": ["filter-tcp=443", "dpi-desync=fake,multisplit", "dpi-desync-split-pos=1,midsld"] }
  ]
}
```

`args` — опции движка без `--`, по порядку применения. Принимаются только опции из белого списка (`EngineOptionCatalog`) с проверенными значениями. Фейковые пакеты задаются только hex-строкой или именем комплектного файла. Пути к файлам, `--debug`, `--wf-raw`, hostlist/ipset в стратегии запрещены: стратегии могут приходить из сети, а движок работает с правами администратора.

## Списки блокировок

Встроенные стратегии и найденные поиском используют три списка, заполнять вручную ничего не нужно:

- `blocked` — заблокированные домены (Re:filter + antifilter community, около 81 тыс.). В нём есть и то, чего нет в реестре РКН, например YouTube и googlevideo. Полный реестр antifilter (32 МБ, около миллиона доменов, в основном казино) не используется.
- автосписок (`--hostlist-auto`) — движок сам добавляет домен, если соединения с ним трижды за минуту обрываются как при блокировке (повторы ClientHello, RST, редирект на заглушку). Ложные срабатывания убираются через `exclude.txt`.
- `general` — свой список. Когда новая версия приложения меняет встроенный `general.txt`, изменения вливаются трёхсторонним слиянием: новые домены дописываются в конец вашего файла, убранные из поставки вычёркиваются, а ваши домены, удаления, порядок строк и комментарии остаются. Для этого в `lists/.bundled` хранится версия, с которой вы начинали.

`blocked-ip` (Re:filter ipsum + antifilter community) доступен в конструкторе, но во встроенных стратегиях не включён. zapret обходит DPI, а не блокировку по IP, и для HTTPS имя сайта и так видно. IP-список нужен только для трафика без имени сайта. Подсети крупнее /16 отбрасываются: в исходных данных там `104.16.0.0/12` (Cloudflare) и `142.250.0.0/15` (Google), и обход на них ломал бы тысячи незаблокированных сайтов.

Списки обновляются при запуске, если старше суток. Скачанное проверяется построчно. Обновление не применяется, если источники недоступны, записей меньше порога или меньше половины от прежнего: в этом случае остаётся старый файл.

Движок считает профиль с пустыми списками профилем «для всех». Поэтому к каждому профилю со списками приложение добавляет `--hostlist-domains=zapret-smart.invalid` и `--ipset-ip=192.0.2.0/32`. Пустой или ещё не скачанный список сужает профиль до нуля, а не расширяет до всего трафика. Это проверяет `tests/engine/guard-live.sh` на живом трафике через NFQUEUE (Linux, root): контрольный прогон без страховки режет посторонний сайт, со страховкой нет. Там же проверяется, что автосписок пополняется при имитации блокировки и что исключения работают.

## Поиск стратегии

1. Каждый сайт из списка проверяется без обхода: TLS-рукопожатие, ответ и чтение не меньше 64 КБ, чтобы поймать блокировки, которые замораживают поток после ~16 КБ. Открывшиеся сайты исключаются.
2. Перебор техник: по одному представителю каждого семейства (multisplit/multidisorder, фейки с разными fooling, autottl, seqovl, fakedsplit и т.д.). Движок запускается с кандидатом, заблокированные сайты проверяются параллельно.
3. Доводка: у двух лучших меняется по одному параметру (позиция разреза, число повторов, fooling, ttl, фейковый пакет).
4. Повторная проверка: победитель прогоняется ещё два раза. Кандидат, который сработал однажды, не выигрывает.

Лимит времени по умолчанию 6 минут. Если движок трижды подряд не запускается, поиск прерывается. Проверки идут мимо системного прокси, иначе проверялся бы прокси, а не обход. Цели, которые не открылись ни с одной техникой, показываются отдельно: это блокировка по IP или подмена DNS, стратегия тут не поможет.

Найденная стратегия сохраняется как своя и перехватывает TCP 80/443. QUIC поиск не проверяет, поэтому UDP не перехватывается: браузер переключится на TCP.

## Сторож

Пока обход включён, сторож раз в 5 минут проверяет www.youtube.com, discord.com и rutracker.org. Первая проверка после включения задаёт базовый уровень. Если две проверки подряд показывают меньше, сторож прогоняет все стратегии и включает ту, что открывает больше сайтов. Текущая стратегия идёт первой, и при равенстве остаётся она. Между переключениями не меньше 30 минут, чтобы стратегии не сменяли друг друга по кругу. Если сайты не открывались с самого начала, сторож не переключает вслепую и советует запустить поиск.

## Работа в фоне

- Пока обход включён, закрытие окна прячет приложение в трей. В меню значка есть включение, выключение и выход.
- Каждый запущенный winws привязан к Windows Job Object с `KILL_ON_JOB_CLOSE`. Если приложение упадёт или его снимут в диспетчере задач, ОС сама завершит движок, и обход не останется работать без интерфейса.
- Списки блокировок обновляются и во время работы, раз в сутки.

## Раздача на телефон

Выключено по умолчанию. Включённое поднимает на ПК HTTP-прокси (порт 8880), и телефон, телевизор или другой компьютер ходит в интернет через него. Соединения с сайтами открывает сам ПК, поэтому движок их видит. Обычная раздача Wi-Fi так не работает: пересылаемые пакеты движок не видит.

Раздача и обход ПК — две независимые службы, каждая со своим движком (winws) и своей стратегией. Прокси открывает соединения только с локальных портов 45000–48999. Движок раздачи запускается с `--wf-lport=45000-48999` и берёт только их, а обход ПК, поиск и сторож запускаются с `--wf-lport-exclude=45000-48999` и эти порты пропускают. Так пакет не обрабатывается дважды, и любую службу можно включить, выключить или перевести на другую стратегию, не трогая вторую. Опции `--wf-lport*` добавлены в форк движка; имя мьютекса winws учитывает их, иначе два экземпляра с одинаковым `--wf-tcp` не запустились бы вместе. Диапазон лежит ниже динамических портов Windows (49152–65535); если все его порты заняты, соединение открывается с системного порта и идёт без обхода, об этом пишется в журнал.

- Прокси работает в той сети, где уже есть ПК и телефон, обычно в домашнем Wi-Fi. На телефон ничего не ставится.
- iPhone настраивается один раз профилем: в домашнем Wi-Fi открыть в Safari `<адрес ПК>:8880/i` и установить профиль. В профиле домашняя сеть и автонастройка прокси (`proxy.pac`) с разрешённым запасным путём напрямую (`ProxyPACFallbackAllowed`). Пока ПК и приложение работают, iPhone в этой сети ходит через ПК; когда ПК выключен, файл автонастройки недоступен, и iPhone идёт напрямую. В самом файле тоже указано «PROXY …; DIRECT». Интервала проверки прокси в настройках iOS нет, это решает система. Имя домашней сети и пароль приложение берёт из Windows через WLAN API (пароль открытым текстом Windows отдаёт только администратору); если ПК подключён кабелем, имя сети вводится в карточке, пароль необязателен. Профиль не подписан (iOS так и напишет), удаляется в Настройках → Основные → VPN и управление устройством. Файл отдаётся только устройствам из локальной сети, потому что в нём пароль Wi-Fi.
- Android такие профили не ставит: там в настройках сети один раз указывается автонастройка прокси с тем же `proxy.pac` или прокси вручную. Ручной прокси при выключенном ПК оставляет эту сеть без интернета.
- Если роутер выдаст ПК другой адрес, телефон будет ходить напрямую, и профиль нужно поставить заново. Чтобы адрес не менялся, его закрепляют за ПК в настройках роутера.
- Если общего Wi-Fi нет, в свёрнутом блоке «Нет общего Wi-Fi» можно включить «Мобильный хот-спот» Windows (через WinRT из Windows PowerShell). Сам он не включается; точку доступа, включённую из приложения, приложение выключает при выходе.
- Кнопка «Проверить» выясняет, видит ли WinDivert трафик устройств на точке доступа без прокси (слой пересылки, только чтение, 20 секунд). От ответа зависит, можно ли сделать раздачу вообще без настройки телефона.
- В прокси пускаются только устройства из локальной сети (10/8, 172.16/12, 192.168/16, link-local). Через него нельзя достучаться до служб на самом ПК (localhost и link-local закрыты, проверяется уже разрешённый адрес) и нельзя слать почту (порты 25, 465, 587). Заголовок запроса не больше 16 КБ и должен прийти за 15 секунд, соединений не больше 256.
- Приложение ставит правило брандмауэра Windows до того, как откроет порт: входящие на порт прокси только из локальной подсети и только для `ZapretSmart.exe`. Прежние входящие правила для `ZapretSmart.exe` при этом снимаются, в том числе запрет, который Windows ставит сама, если в её окне «Разрешить доступ» нажали «Отмена». Запрет сильнее разрешения, и с ним телефон получал бы таймаут. Выключение раздачи правило убирает.
- Журнал раздачи пишется в `%APPDATA%\ZapretSmart\share.log` и дублируется в журнал на вкладке «Обход»: адрес для телефона, подключения устройств, запросы `/i` и `/proxy.pac`, ошибки (DNS, недоступный сервер, запрещённый порт, таймаут заголовка) и первое удачное соединение с каждым сервером. Одинаковые строки от устройств пишутся не чаще раза в минуту, файл больше 1 МБ переименовывается в `share.old.log`. Кнопка «Журнал раздачи» в карточке открывает файл.
- Кнопка «Проверить связь с телефоном» минуту ждёт подключения телефона и говорит, где рвётся связь. Сначала она подключается к порту с самого ПК (слушает ли прокси), потом смотрит брандмауэр Windows («Блокировать все входящие») и сторонние брандмауэры из Центра безопасности. Затем через WinDivert (только чтение) ловит попытки подключения к порту на слое NETWORK, то есть раньше, чем их увидит брандмауэр. Попытки дошли до ПК, но не до приложения: режет брандмауэр на ПК. Не дошли совсем: роутер (изоляция клиентов, гостевая сеть) или телефон в другой сети.
- Кнопка «Найти мешающие программы» ищет файрволы, антивирусы и VPN, которые не пускают телефон к ПК. Она подключается к своему тестовому порту по адресу ПК в сети и по 127.0.0.1, под аудитом WFP смотрит, какой фильтр отбросил подключение (прежняя политика аудита сохраняется через `auditpol /backup` и возвращается `/restore`), выгружает фильтры WFP (`netsh wfp show filters`) и сверяет их и запущенные процессы со списком известных программ: Portmaster, Kaspersky, ESET, Avast/AVG, Bitdefender, Norton, Comodo, GlassWire, simplewall, Windows Firewall Control, TinyWall, NetLimiter, AdGuard, VPN-клиенты с kill switch, чужие zapret и GoodbyeDPI. Для каждой найденной сказано, что в ней выключить. Работает и без включённой раздачи.

### Телефон не подключается

Если адрес ПК не открывается с телефона (таймаут), по порядку:

1. «Проверить связь с телефоном»: слушает ли прокси, доходят ли пакеты до ПК.
2. «Найти мешающие программы», если проверка сказала, что подключение режется на ПК. Частые виновники: Portmaster (по умолчанию блокирует все входящие: Apps → ZapretSmart → выключить «Force Block Incoming Connections» и «Force Block LAN»), сетевой экран антивируса (неподписанный ZapretSmart.exe попадает в ограниченные), kill switch VPN-клиента. Пауза защиты не выгружает сетевые драйверы антивируса.
3. Если до ПК не доходит ни одной попытки: изоляция клиентов на роутере, гостевой Wi-Fi, VPN или «Частный узел» на телефоне.
- Через прокси идут браузеры и большинство приложений. UDP через HTTP-прокси не ходит, поэтому звонки и голосовые чаты идут мимо ПК без обхода, а QUIC откатывается на TCP.

## Файл hosts

Выключено по умолчанию. Включённое дописывает в системный `hosts` адреса GitHub, Telegram и Discord из [списка Flowseal](https://github.com/Flowseal/zapret-discord-youtube) (MIT), чтобы они открывались при подмене DNS. Свежий список скачивается вместе со списками блокировок; если GitHub недоступен, берётся последний скачанный, а если его нет, снимок `hosts/flowseal.hosts` из поставки.

- Приложение правит только свой блок между метками `# >>> Zapret Smart` и `# <<< Zapret Smart` в конце файла. Всё остальное остаётся байт в байт, в том числе комментарии в cp1251: файл читается и пишется побайтно.
- Если имя уже задано вами вне блока, его запись не ставится: при совпадении Windows берёт первую, и главной остаётся ваша.
- Перед каждым изменением копия файла сохраняется в `%APPDATA%\ZapretSmart\hosts.backup`. Выключение убирает блок и возвращает файл к исходному виду.
- Строки источника проверяются: нужен IP-адрес и доменное имя, больше 2000 записей не принимается. Адреса обновления Windows и `localhost` переопределить нельзя. Подмена адреса не даёт подменить содержимое: сертификат сайта проверяется как обычно.

## Версии

В настройках можно загрузить список опубликованных версий и поставить любую: обновиться или откатиться. Архив скачивается только со страницы релизов этого репозитория и сверяется по SHA-256 с `SHA256SUMS.txt` того же релиза; при несовпадении ничего не ставится. Файлы меняет скрипт PowerShell после выхода приложения: он заменяет только изменившиеся файлы, при ошибке возвращает прежние из резервной копии и запускает приложение снова. Итог пишется в `%APPDATA%\ZapretSmart\update.log` и показывается в журнале при следующем запуске. Настройки, свои стратегии и списки лежат отдельно и не затрагиваются.

## Оформление

Шесть тем, переключаются в настройках на лету:

| Тема | Палитра | Фон |
| --- | --- | --- |
| Графит | тёмная, бирюзовый акцент (по умолчанию) | нет |
| Светлая | светлая, тёмно-бирюзовый акцент | нет |
| Хакер | зелёный терминал, моноширинный шрифт | бинарный дождь |
| Хэллоуин | фиолетовая ночь, тыквенный оранжевый | луна, искры, летучие мыши |
| Зима | холодный синий | снегопад |
| Ретровейв | неоновый розовый на фиолетовом | закатное солнце и бегущая сетка |

Контраст текста в каждой теме проверяется тестами по WCAG: основной текст не ниже 7:1, подписи, ошибки и предупреждения не ниже 4.5:1. Фон анимируется, только пока окно видно: в свёрнутом и спрятанном в трей окне он стоит. Движение фона можно выключить в настройках, тогда остаётся неподвижная картинка. Кадр дождя рисуется из заранее отрисованных спрайтов, около 4 мс при программной отрисовке окна 1100×720.

Меню бывает колонкой слева или строкой сверху (настройка «Меню сверху»).

## Анимации

Анимируются только прозрачность и трансформации, переходы короче 200 мс, кривая ease-out `0.23, 1, 0.32, 1`. Если в Windows выключены эффекты анимации, движение убирается, остаётся плавная смена прозрачности и цвета, а фон темы неподвижен.

- Вкладка появляется за 110 мс. При переключении с клавиатуры без анимации: стрелками листают быстро, и она бы отставала. Журнал движка виртуализирован: из 500 строк раскладываются только видимые, поэтому возврат на главную вкладку не дороже остальных.
- Смена темы: снимок окна в старой теме гаснет поверх новой за 180 мс, палитра меняется одним движением.
- Кнопки при нажатии сжимаются до 97 %, цвет при наведении меняется за 100 мс. «Включить» и «Выключить» стоят на одном месте и сменяют друг друга коротким кроссфейдом.
- Кольцо у индикатора статуса расходится три раза при включении обхода и затихает. Без остановки оно пульсирует, только пока сторож подбирает стратегию.
- Подтверждение удаления появляется из кнопки, а не из центра. Итог поиска, статус сторожа и ошибки проявляются, а не выскакивают.

## Обмен с сообществом

Выключен по умолчанию. Сервера базы пока нет, поэтому ничего никуда не отправляется. Правила уже зафиксированы в коде и тестах (`CommunityReports`):
- отчёт содержит только ASN, регион (субъект), параметры стратегии и метрики;
- отчёт формируется, только если поиск шёл по стандартному набору сайтов: свой набор — это отпечаток интересов человека;
- стратегия из базы проходит тот же белый список, что и всё остальное.

dotnet run --project src/ZapretSmart.App

Движок собирается в Cygwin (`gcc-core`, `make`, `zlib-devel`): `make -C engine/nfq cygwin64`. Готовую сборку (GUI + winws.exe + WinDivert + cygwin1.dll) собирает CI: артефакт `ZapretSmart-win-x64`.

Если задать `ZS_ENGINE=<путь к winws.exe или nfqws>`, тесты дополнительно прогонят пресеты, все допустимые значения опций и все кандидаты поиска через `--dry-run` настоящего движка. С `ZS_LIVE=1` и winws.exe (Windows, права администратора) запускается настоящий перехват через WinDivert.

Свои стратегии и списки доменов лежат в `%APPDATA%\ZapretSmart`.
